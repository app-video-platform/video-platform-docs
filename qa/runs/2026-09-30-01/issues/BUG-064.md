# BUG-064 — Successful onboarding save resets the wizard to Welcome

- Severity: High — a valid profile save prevents progress beyond Basic Profile.
- Status: Confirmed in the deployed browser; not fixed.
- Cases: PROF-001, PROF-018; profile persistence evidence also supports PROF-019.
- Observed: 21 October 2026, approved synthetic Creator account.

## Reproduction

1. Set only the synthetic Creator's onboarding completion flag to false.
2. Open `/app/onboarding`, which exposes the wizard. The normal `/onboarding` entry still renders Dashboard (BUG-035).
3. Advance Welcome → Basic Profile, enter `Synthetic QA Creator profile October21`, and click Next.
4. The wizard returns to Welcome instead of retaining About You.
5. Advance to Basic Profile again and submit the saved title. Welcome returns again.

The title persists: a full browser reload and return to Basic Profile shows the exact title. The read-only database account independently confirms the saved title while the completion flag is false. The reset therefore occurs even when persistence succeeds. Additional information and its social editor cannot be reached through these normal Next actions.

## Source explanation

`updateUserDetails.pending` sets the shared authentication `loading` flag. `ProtectedRoute` returns a Spinner in place of its children while that flag is true. This unmounts the wizard; when the request completes, the new `MultiStepForm` starts with `useState(1)`. This source inference is consistent with both observed successful-save resets; no browser state injection or intercepted response was used.

## Evidence and cleanup

The existing consolidated browser evidence batch contains packet `deployed-onboarding-save-reset-and-storage-completion-2026-10-21`. Private runtime screenshots retain the reset and profile reload. The synthetic Creator's completion flag was restored to true, and its synthetic title is retained for future profile tests. No human profile was changed.
