# BUG-054 — Older Admin filter response replaces newer results

- Severity: Medium — Admin audit rows can contradict selected filters.
- Cases: ADMIN-011 and ADMIN-007.
- Environment: actual current local browser/backend/PostgreSQL; no deployed parity claim.

## Reproduction

1. Open Admin Audit and enter the exact disposable Product target ID with21 actual persisted events.
2. Change Target type to `pRoDuCt`, then promptly change Action to `product_create`.
3. Allow both actual requests to finish.

Expected: selected create action shows the one Product creation event.

Actual: Action remains `product_create`, while the table shows20 events including19 Product updates. The create-filtered200 response completed at16:35:41.858UTC; the older type-only200 response completed at16:35:41.859UTC and replaced it. This occurred once naturally. Changing the Action alone to mixed-case create then produces the correct single event.

The API separately returns one creation event and19 updates. Current Admin reducer accepts every fulfilled audit request into `auditPage` without checking the active request/query. Product data and permissions are unchanged.

Existing browser batch key `local-current-app-actual-query-serialization-and-admin-audit-2026-10-12` contains normal DOM, actual request completion order, paired API responses and current page/reducer source. Browser Next control limitation is recorded separately, not treated as this defect.
