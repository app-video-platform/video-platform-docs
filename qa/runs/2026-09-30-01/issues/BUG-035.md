# BUG-035 — Onboarding URL renders the role home instead of the wizard

- Severity: High — the normal onboarding entry does not expose its wizard.
- Status: Confirmed in the current local full router; route symptom also observed in the deployed signed-in session.
- Cases: PROF-001; prerequisite for PROF-002/003.
- Observed: 4 October 2026. Report finalized from retained evidence on 7 October.
- Frontend revision: `12765d4568796f8472124383a221b74d82850c5b`; deployed revision unknown.

## Expected

An authenticated profile with incomplete onboarding can open `/onboarding` and start the Welcome → Basic → About → Additional → summary flow.

## Actual and reproduction

1. Open `/onboarding` in the full current frontend with a synthetic authenticated profile whose `onboardingCompleted` is false.
2. For USER, observe the ordinary home page; for CREATOR, Dashboard; for ADMIN, Admin home.
3. The wizard and onboarding fields are absent in every fixture.

A separate existing signed-in deployed browser at `/onboarding` shows Dashboard before and after a settled reload, without a wizard. Its profile completion flag, current role and deployed revision were not independently queried. The intermediate loading snapshot is retained separately and is not used to establish this result.

## Implementation and limits

`App.tsx` mounts `AppRouter` at the outer `/onboarding` route. That router defines its own `/onboarding` route and a separate `/` layout/index selecting `RoleHome`. The executed full-router fixtures select role home at the outer onboarding URL.

A diagnostic route mounting the unmodified Onboarding component directly does render the wizard. This establishes the distinction between route selection and component behavior; it is a test fixture, not an application fix. No real profile, role or account changed. Later field persistence, location and social-link assertions remain unexecuted through the normal route.
