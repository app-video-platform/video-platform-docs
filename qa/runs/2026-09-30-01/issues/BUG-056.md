# BUG-056 — Password hints move Sign in during the first click

- Severity: Medium — normal pointer submission needs an extra click or prior blur.
- Cases: AUTH-010, AUTH-011.
- Environment: current-source local frontend, actual backend and migrated PostgreSQL, 14 October 2026. Observed at 1280px. No deployed reproduction claimed.

## Reproduction

1. Open `/auth/login` as Guest. Enter a verified synthetic User's valid credentials.
2. Keep the password field focused: its five password hints are visible.
3. Click Sign in once using the normal browser pointer control.
4. Hints disappear and Sign in moves upward by 120px. The form remains on login and sends no login request.
5. Click the now-stationary Sign in button again. The actual backend returns 200, profile loads with 200 and the app opens normally.

The first-click failure is reproduced twice, including a clean form without old errors or active service faults. Button top coordinates change 397.609375→277.609375 and 380→260, retaining 40px height. The trace records no request for either first click, then actual login/profile 200 for recovery without changing credentials.

## Related validation effect

After an initial blank submit, typing a valid password and clicking Sign in from the focused password field leaves the old Password is required error visible. Its password-rule DOM shows the actual value meets length/lowercase/uppercase/number checks. Blurring to Email before clicking hides the hints first; submission then correctly removes the password error and retains only Email is required. The button moves 415.21875→295.21875 in this control.

## Expected

The first click after entering credentials submits the form or refreshes its validation reliably. Focus feedback does not move the action out of the pointer's activation path.

## Source and evidence

`PasswordInput` conditionally renders the hint list only while focused and removes it on blur. The SignIn page places its submit button below that component. Current-source inspection supports the observed layout mechanism; browser/geometry/request traces establish the failure.

Existing evidence batch key: `local-actual-signin-validation-rejection-and-password-hint-click-2026-10-14`. It contains DOM observations, button geometry, credential-free method/path/status traces, source snapshots and database controls. Actual credentials/cookie values are not included. Normal first-click failure was previously treated as an unexplained browser-action limitation; the earlier AUTH-010 overall Pass is superseded by Fail while its positive onboarding/reload variations remain retained.

No implementation change was made. Server rejection feedback is a separate AUTH-012 clarification; the development-only error overlay is not a product feedback feature.
