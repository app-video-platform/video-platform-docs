# BUG-041 — Rejected nonowner Product deletion calls storage cleanup

- Severity: High — another Creator can reach deletion of an owner's media objects despite an HTTP403 response.
- Status: Storage deletion calls confirmed with current handlers and a mock storage adapter; real object deletion was deliberately not executed.
- Case: MEDIA-013.
- Observed: 7 October 2026.

## Expected

A nonowner deletion request is rejected before any external object cleanup. An HTTP403 and database rollback must leave the owner's media objects untouched.

## Actual and reproduction

1. Creator A creates a Draft Product and uploads two synthetic gallery images. GET Product confirms both saved media records.
2. A distinct Creator B sends DELETE `/api/products/{id}` using B's own valid JWT and matching CSRF.
3. The request returns HTTP403. GET Product as A confirms that the Product and both gallery records remain after transaction rollback.
4. The storage adapter nevertheless received two `delete` calls with A's exact Product gallery object keys during B's request.

The same behavior occurs for Course, Download, Consultation and Membership. Separate owner and Admin controls return 204, remove Product/media metadata and invoke the expected two storage cleanup calls.

## Implementation and limits

`ProductService.deleteProduct` calls `productMediaService.removeAll` before the Product handler checks ownership. `removeAll` deletes and flushes media records, then calls the storage adapter. The later authorization failure rolls back database changes, but cannot reverse an external deletion that has already happened.

This is an actual authorization and transaction integration test against an isolated migrated PostgreSQL database. Storage is mocked: the report proves that unauthorized requests invoke deletion with the owner's keys, not that real Spaces objects were removed. No cloud Product, file, role or database was changed by this test. Assessing real storage consequences remains part of the unfinished case.

## Evidence

[Backend evidence](../evidence/backend-content-session-batch-2026-10-03.json), entry `migrated-postgresql-product-media-order-and-authorization`, retains twelve role/type deletion assessments, 84 request observations, distinct synthetic requester IDs, exact adapter calls and post-request gallery readbacks. Four nonowner assessments fail; eight owner/Admin controls pass.

No application fix was made.
