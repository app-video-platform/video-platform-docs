# BUG-040 — Valid gallery swaps fail the PostgreSQL position constraint

- Severity: Medium — saved gallery images cannot be reordered through a valid swap.
- Status: Confirmed through current API handlers, migrated local PostgreSQL and deployed development API/PostgreSQL. Native browser reorder remains unverified.
- Case: MEDIA-014.
- Observed: 7 October 2026.

## Expected

A complete permutation of the existing gallery IDs succeeds and persists the requested positions.

## Actual and reproduction

1. Create a disposable Draft Product using its API. Upload three small raw PNG bodies through the gallery endpoint; GET Product confirms positions 0, 1 and 2.
2. As the Creator owner or Admin, PUT `/api/products/{id}/media/gallery/order` with the first two IDs swapped and every ID present exactly once.
3. The API returns HTTP400. Its error names `uq_product_media_kind_position` and a duplicate `(product_id, kind, gallery_position)` value. GET Product confirms that the original order remains.
4. Delete the middle image. The deletion succeeds and normalizes the remaining positions to 0 and 1. Swapping those two remaining IDs fails with the same constraint error and unchanged persisted order.

Both variants fail for Course, Download, Consultation and Membership, under owner and Admin identities: sixteen failed swaps. Unchanged valid order controls pass. Duplicate, missing, foreign and empty order submissions correctly return 400 and preserve the original gallery.

## Implementation and limits

The migration creates an immediate unique index on `(product_id, kind, gallery_position)`. `ProductMediaService.reorder` directly assigns final positions to the existing rows and saves them. During a swap, one row takes another row's still-occupied position.

The test uses actual Spring security, controller/service/transaction handlers, PostgreSQL 15.19, all forty migrations and Hibernate schema generation disabled. The storage adapter is mocked and consumes the actual synthetic upload stream; these observations prove database ordering behavior, not object delivery or a deployed browser journey. No application fix or cloud mutation was made.
