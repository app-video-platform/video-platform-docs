# BUG-021 — Article reader displays editor JSON instead of formatted text

- Severity: Medium — saved Article content is readable only as serialization text.
- Status: Confirmed for the authenticated owner and a separately entitled learner.
- Case: DISC-021.
- Product: `cb045295-cf70-445c-99a7-46fc0618e58e`.
- Article: `f0a89669-5d92-4c5a-8875-316c3e77dd41`.
- Observed: 1 October 2026; deployed revision unknown.

## Reproduction

1. Save `QA article body A` in the current Article editor with Bold applied.
2. Open the Published Course public Product route as its authenticated owner.
3. Inspect Course content, then reload.

## Expected and actual

The Article should render its saved text and formatting. Instead, both reads display the entire Tiptap JSON string, including type, content and marks keys. The Article has no rendered bold element. The database contains the expected bold mark; the save itself succeeded.

Guest reads correctly omit the private body. This is a rendering defect, not evidence of an anonymous content leak. HTML and unsafe-markup fixtures, and a separate entitled learner, were not tested.

## Diagnostic context

Local `product-page.component.tsx` passes `lesson.content` through `DOMPurify.sanitize` into `dangerouslySetInnerHTML`. The current Article editor stores Tiptap JSON as a string. This format mismatch is consistent with the observed output. No implementation change was made.
