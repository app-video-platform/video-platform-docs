# BUG-051 — Final content deletion leaves an incomplete Product Published

- Severity: Medium — public availability and shared editing disagree about required content.
- Case: PROD-028, Course and Download nested deletion variants.
- Environment: unchanged current frontend and actual backend with40 Liquibase migrations on isolated PostgreSQL. Synthetic Creator owns fresh disposable Products. No deployed parity claim.

## Reproduction

1. Prepare a Published Course containing exactly one Article, or a Published Download containing exactly one confirmed file metadata row.
2. As the owner, remove that final item through the canonical nested lesson/file DELETE endpoint.
3. GET the Product as owner and Guest; reload its public page and Creator Overview.
4. PATCH an ordinary shared field such as the unchanged description.

Expected: minimum publication requirements remain consistent across supported mutations. Removing the final required item should reject the removal or move the Product out of Published availability; ordinary editing should not discover a contradictory state afterward.

Actual: DELETE returns204. Owner GET still returns PUBLISHED withzero lessons/files. Guest GET and the public storefront still expose the Published Product; normal public Product page and Overview render it. The following unchanged-description PATCH returns422 with `details.lessons` or `details.files` because the shared publication validator requires the content that the nested mutation just removed.

## Verified controls

- Before deletion, blank-name PATCH422 reports `name`; GET retains original name, Published state and one content item.
- Both Course and Download reproduce the final-item inconsistency independently.
- Supported restoration of an Article/file metadata row returns201; shared PATCH then200 while Published.
-97 existing grants and35 orders are unchanged. Both targets havezero entitlements. Only newly disposable local content was deleted/restored.
- Download fixture contains test-only metadata for an explicitly nonexistent synthetic object key. No binary upload, delivery or cloud object deletion is claimed.

## Implementation evidence

`ProductPublicationValidator` requires a Course lesson or Download confirmed file when validating a Published Product. Canonical `CourseLessonService.deleteLesson` and `FilesService.deleteFile` delete the child and update the Product timestamp without invoking that validator or changing publication status.

No new evidence file was created. Browser shared editing remains separately blocked by BUG-001; this API finding does not complete that browser step.
