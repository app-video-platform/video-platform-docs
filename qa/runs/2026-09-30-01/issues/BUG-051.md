# BUG-051 — Final content deletion leaves an incomplete Product Published

- Severity: Medium — public availability and shared editing disagree about required content.
- Case: PROD-028, Course and Download nested deletion variants.
- Environment: unchanged current frontend and actual backend with40 Liquibase migrations on isolated PostgreSQL. Synthetic Creator owns fresh disposable Products. No deployed parity claim.

## Reproduction

1. Prepare a Published Course containing exactly one Article, or a Published Download containing exactly one confirmed file metadata row.
2. As the owner, remove that final item through the canonical nested lesson/file DELETE endpoint.
3. GET the Product as owner and Guest; reload its public page and Creator Overview.
4. PATCH an ordinary shared field such as the unchanged description.

Expected: minimum publication requirements remain consistent across supported mutations. Removing the final required item should reject the removal or move the Product out of Published availability; ordinary editing should not discover a contradictory state afterward.

Actual: DELETE returns204. Owner GET still returns PUBLISHED withzero lessons/files. Guest GET and the public storefront still expose the Published Product; normal public Product page and Overview render it. The following unchanged-description PATCH returns422 with `details.lessons` or `details.files` because the shared publication validator requires the content that the nested mutation just removed.

## Verified controls

- Before deletion, blank-name PATCH422 reports `name`; GET retains original name, Published state and one content item.
- Both Course and Download reproduce the final-item inconsistency independently.
- Supported restoration of an Article/file metadata row returns201; shared PATCH then200 while Published.
-97 existing grants and35 orders are unchanged. Both targets havezero entitlements. Only newly disposable local content was deleted/restored.
- Download fixture contains test-only metadata for an explicitly nonexistent synthetic object key. No binary upload, delivery or cloud object deletion is claimed.

## Implementation evidence

`ProductPublicationValidator` requires a Course lesson or Download confirmed file when validating a Published Product. Canonical `CourseLessonService.deleteLesson` and `FilesService.deleteFile` delete the child and update the Product timestamp without invoking that validator or changing publication status.

[Existing browser/API batch](../evidence/browser-populated-reporting-batch-2026-10-03.json), key `local-current-app-actual-published-content-validation-2026-10-10`, contains actual responses, normal page snapshots, scope limits, source hashes and final database readbacks. No new evidence file was created. Browser shared editing remains separately blocked by BUG-001; this API finding does not complete that browser step.

## Backend review handoff — 2 November 2026

Local fix, not committed or deployed. A Published Course now rejects deletion
of its final section or lesson; a Published Download rejects deletion of its
final confirmed file, including removal of the containing section. The API
returns HTTP 422 with field-keyed errors and asks the author to hide the
Product first. Removing other content remains supported. Hidden/Draft content
can still be removed. Existing invalid Published records are not rewritten.

`ProductContentDeletionGuard` locks and refreshes the concrete Product before
checking remaining persisted content. Generic PUT/PATCH updates acquire the
same lock before publication validation. A second refresh under the held lock
handles Hibernate's follow-on locking for inherited Products. Canonical and
legacy Course deletion paths use the same guard. Deletion also removes the
child from its managed parent collection before saving, avoiding stale
references to deleted rows. No schema migration is required.

Regression coverage is in `ProductControllerIntegrationTest` (Course and
Download publication, final content/section rejection, non-final removal,
shared edits, and Hidden removal) and
`ProductContentDeletionConcurrencyTest` (two competing lesson deletions, only
one succeeds, Published state retains one lesson). The focused API/service
run passed 45 tests. Both new API scenarios and the concurrency scenario
passed against isolated PostgreSQL 15 with all 43 Liquibase migrations;
provider storage is mocked and no cloud data was changed. The full backend
suite passed 153 tests with zero failures, errors, or skipped tests.

OpenAPI deletion responses, backend context, and the developer authoring page
are updated. Documentation typecheck and build passed. Product documentation
should reflect the hide-first workflow when the fix is merged. No deployed
browser retest is claimed.

Final PostgreSQL rerun on the completed implementation passed all three
scenarios. Trello is in Dev done for review.
