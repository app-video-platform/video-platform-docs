# BUG-014 — Search retains or overwrites the wrong page state

- Severity: Medium
- Status: Confirmed; not fixed in this test execution pass
- Related case: DISC-011
- Role: Guest
- Environment: deployed frontend; existing synthetic Published Consultation

## Reproduction

1. Direct-load `/app/explore/search?term=&page=1` to reach the second result page.
2. Search `QA-2026-09-30-01 Consultation` using the navbar Submit search button.
3. Inspect the results, then click Prev.
4. Use browser Back to revisit the previous second-page search.

## Expected

A new search starts at its first page. Browser history restores the requested term and page without replacing them with stale component state.

## Actual

The new search retains `page=1`, displays `No products found` and `Page2of1`, although the same Product appears in autocomplete. Clicking Prev immediately reveals the matching Product.

Browser Back then loses the previous second-page selection: its `page=1` parameter is overwritten, and first-page results appear. The navbar also retains the later query while the result heading follows the previous term.

## Diagnostic context

Local `search-page.component.tsx` initializes page state from the URL once, does not reset it when the term changes, and writes state back to the URL. This is consistent with the observed behavior; the deployed revision is unknown.

No Product, account or commerce data was modified.

## Deployed four-role confirmation — 23 October 2026

Guest, synthetic User, synthetic Creator and approved temporary synthetic Admin each reproduce both failures. From blank-term page two, submitting the exact synthetic Published Download title keeps `page=1`, shows zero results and `Page 2 of 1`. Prev reveals the matching Download. Back then returns to blank-term page zero, losing the earlier page-two state. Forward returns to the recovered single-result first page.

Direct negative and malformed page values each normalize the URL and return twenty first-page cards, while Prev remains enabled. Those policy edge expectations remain recorded as Needs clarification; they do not erase the independently confirmed stale query/history failures.

The temporary Admin was restored to Creator and verified in the browser. No catalog or grant data changed. The existing consolidated evidence packet `deployed-search-url-state-four-role-matrix-2026-10-23` records all actual query, row-count, empty-state, pagination and boundary observations.
