# BUG-031 — Changing saved Storefront and landing orders fails

Severity: High. Cases: STORE-008 and LAND-002. Confirmed in the development deployment on 3 October 2026; deployed build identities remain unknown. Actor OWNER-A, CREATOR.

## Storefront reproduction

1. Save an initial custom order containing own Published and Hidden Products.
2. Reload the builder and move the Hidden `QA 2026-10-03 Free Course` one position up.
3. Click Save changes.

Actual: Save rejects with `duplicate key value violates unique constraint uk_storefront_product`, from an update of an existing collection position. The draft remains unsaved. Reset/reload returns the previous saved order; no Product record changes.

Expected: a valid permutation of unique owned Product IDs saves and survives reload.

## Landing reproduction

1. Save a landing config with a custom section order, or save the default order first.
2. Move Creator up/down so the saved order changes while ABOUT/CONTENTS/CREATOR each still occur once.
3. Click Save.

Actual: Save rejects with `duplicate key value violates unique constraint uk_landing_order_section`. Reproduced through the real owner editor for Course, Download, Consultation and Membership. Failed changes roll back: prior description/layout/visibility/order survive reload. The UI exposes the underlying SQL error.

Expected: a valid three-section permutation replaces the saved order atomically.

## Evidence and diagnosis

[Deployed browser/database/log batch](../evidence/browser-populated-reporting-batch-2026-10-03.json) retains the actual failed drafts, error messages, Reset/reload results and read-only checkpoints. Keys include `live-storefront-existing-order-constraint-failure`, `live-storefront-existing-reorder-settled-comparison`, `live-landing-course-saved-reorder-failure`, three `live-landing-existing-reorder-failure-*` nodes and `saved-order-final-database-and-logs`.

The first Storefront baseline in the failure node was captured while Products were loading; it is inconclusive. The settled prior saved-order observation and final database comparison establish rollback. Five sanitized log events match the constraint errors at18:04:26,18:16:33 and18:21:52/55/58 UTC. No request IDs were captured; raw logs were omitted.

[Local constraint reproduction](../evidence/backend-product-ownership-publication-batch-2026-10-03.json), key `migrated-saved-order-constraint-reproduction`, reproduces the failures for all four landing types and Storefront using the migration's unique constraints. Actual local rejection status400, followed by exact persisted-state equality. Successful same-order updates isolate the problem to changing an existing ordered collection. Passing reproduction methods do not mean the product behavior passes.

Migrations37/38 enforce uniqueness of each Product/section within its configuration. Entities use ordered element collections without those collection unique constraints in generated table metadata. Services clear/refill managed lists; Hibernate issues per-position updates, which can collide with another existing position during a swap. This is an implementation-backed explanation, reproduced locally with the constraints and consistent with the deployed PostgreSQL errors. No fix is included.
