# BUG-004 — Explore Creator link opens a blank route

- Severity: Medium
- Case: DISC-004, guest-creator-link
- Deployment versions: unknown
- Account: Guest
- Fixture: Course `ddd5bb80-183e-48d5-84cd-8819ca082a58`, owner OWNER-A

## Reproduction

1. Open `/app/explore` without signing in.
2. Locate `QA-2026-09-30-01 Course`.
3. Click its Creator name.

Expected: the Creator storefront opens. The owner's verified working storefront is `/app/store/a1ebdc7a-d497-4334-9fed-309aec071b25`.

Actual: navigation uses `/store/a1ebdc7a-d497-4334-9fed-309aec071b25`; the page is blank apart from the notification container.

Reproduced once. The catalog flagged this routing inconsistency for investigation; the working storefront establishes the intended destination. No content or account changes are needed for reproduction.

Evidence: [blank destination](../evidence/explore-creator-link-blank.jpg).

Guest, synthetic User, Creator and temporary Admin each click the Creator name on the same existing synthetic Consultation card. All navigate to `/store/{creatorId}` with no rendered root text or h1. Direct `/app/store/{creatorId}` renders the Storefront in each same viewer session. The actual Product owner remains a Creator throughout; only the separate synthetic viewer is temporarily Admin. No Product or ownership mutation occurs. Temporary Admin is restored to Creator and verified in the fresh browser Dashboard.

Consolidated packet: `deployed-explore-creator-link-four-role-matrix-2026-10-23`. Original DISC-004 is now fully assessed Fail; the earlier Guest-only reproduction remains historical evidence.
