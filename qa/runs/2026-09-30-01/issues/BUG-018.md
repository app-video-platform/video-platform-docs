# BUG-018 — Reopening an Article editor restores stale content and can overwrite the saved body

- Severity: High — ordinary follow-up editing can replace saved Course content.
- Status: Confirmed; no implementation changes in this execution pass.
- Case: CONTENT-012.
- Role: OWNER-A, CREATOR.
- Deployment versions: unknown; observed on 1 October 2026.
- Disposable Course: `cb045295-cf70-445c-99a7-46fc0618e58e`.
- Section: `d87b3e72-d4f9-4f4f-ad4a-6ca6554423cc`.
- Article lesson: `f0a89669-5d92-4c5a-8875-316c3e77dd41`.

## Reproduction

1. Create a Course and stay in its initial working creation session.
2. Create an Article lesson, open its editor, enter `QA article body A`, apply Bold, and wait for Saved.
3. Verify that the database contains the corresponding Tiptap JSON with a bold mark.
4. Close and reopen the same lesson editor without leaving the Product workspace.
5. Repeat closing and reopening: the editor displays `Start writing your lesson…`, rather than the saved body.
6. Append ` QA appended text B` to the displayed paragraph and wait for Saved.

## Expected

Reopening the editor displays the latest saved Article body and formatting. A follow-up edit starts from that body.

## Actual

Both reopening attempts display the initial starter paragraph. The original body still exists in the database before the follow-up edit, so this is a rehydration failure rather than a failed first save.

After appending text to the reopened editor, the database contains only `Start writing your lesson… QA appended text B`. The original `QA article body A` and its bold mark have been overwritten. Description and lesson identity remain intact.

This is confirmed for a newly created Article within the initial mounted workspace. Broader existing-Article scope is not established because saved workspace reopening is separately obstructed by BUG-001.

## Diagnostic context

Local `lesson-editor.component.tsx` memoizes `parseArticleContent(lesson.content)` with only `lesson.id` as a dependency. A newly created lesson initially has no body. The memoized initial content therefore remains empty after subsequent content changes, and reopening the rich-text editor uses its starter paragraph. This is consistent with the observed behavior; the deployed revision is unknown.

The database accepted both saves. No original user content was edited. The disposable lesson's first synthetic body is restored through the UI after recording the reproduction; verify the cleanup evidence before retesting.

Cleanup verified: [read-only DB checkpoint](../evidence/curriculum-lessons-and-quiz-db.json) confirms the original bold `QA article body A` is restored.
