# BUG-068 — Saved Storefront builder default differs from the public page

- Severity: Medium — the builder preview and featured marker misrepresent the current public Storefront.
- Status: Confirmed in the deployed browser; not fixed.
- Case: STORE-020; earlier default-order uncertainty is retained as historical evidence.
- Role: Approved synthetic Creator; public read also supports Guest.
- Observed: 22 October 2026.

## Reproduction

1. Use the retained synthetic Creator with Published Downloads Alpha, Beta and Gamma.
2. Keep the persisted Storefront configuration at its original defaults: featuredProductId null and productOrderIds empty.
3. Reload Storefront Builder. It says all configuration changes are saved and Save changes is disabled.
4. Compare its preview with the public Storefront for the same Creator.

Builder catalogue order is Alpha, Beta, Gamma and its featured Product is Alpha. The public API/page order is Gamma, Beta, Alpha and the public page features Gamma. Both screens are freshly loaded with the same persisted logical configuration. Expected: the saved builder preview/default featured marker reflects the live public result for that Creator.

## Source explanation and controls

The builder’s orderStorefrontProducts returns its input array unchanged when no explicit order exists; its view model features the first eligible Product. The public backend independently orders remaining Products newest-created first with an ID tie-break. The public view model also features its first eligible Product. Different input ordering therefore yields different visible defaults.

Explicit configured ordering agrees between builder and public page. Null selection and a formerly Published selection that becomes Hidden both fall back to eligible Products; hidden/draft Products are omitted. A direct Hidden selection is correctly rejected400. These positive boundaries do not resolve the empty-config preview mismatch.
