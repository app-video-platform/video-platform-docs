# BUG-027 — Cart and wishlist menus use near-white text on white panels

- Severity: Medium — collection details and empty-state text are difficult to read.
- Case: CART-017, deployed empty-menu readability and local populated-menu readability.
- Scope: deployed empty Cart/Wishlist menus confirmed; populated item text confirmed in isolated local frontend.
- Deployed frontend/backend revisions: unknown. Local frontend revision: `12765d4568796f8472124383a221b74d82850c5b`.
- Fixture: OWNER-A temporarily User with empty browser-local collections; local synthetic one/99/100-item collections. No collection mutation or checkout transaction.

## Reproduction

1. Use a signed-in User on /app and open Open shopping cart.
2. Observe the white panel with almost-white empty-state text and pale action text.
3. Open Open wishlist and observe the same empty-state issue.
4. In the isolated collection harness, open populated menus and observe almost-white item names/prices on the same white panel.

Expected: visible collection details and empty-state labels are readable against their menu background. Actual: deployed paragraph color is `rgb(248, 249, 250)` on `rgb(255, 255, 255)`; action text is also pale. Local populated titles/prices inherit the same near-white body color.

## Verified local cause

Cart/Wishlist-specific SCSS overrides the shared dropdown background with `white`. Paragraphs, item spans and the shared action styles retain colors intended for dark app surfaces. Both menus use the same incompatible foreground/background combination. Align those menu surfaces and text colors; no implementation repair is part of this pass.
