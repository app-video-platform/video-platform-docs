# BUG-055 — Membership file selection is cleared by uploader reinitialization

- Severity: High — Video and Resource metadata cannot be saved through the normal editor.
- Cases: MEM-003, MEM-004; related Course selection display in CONTENT-013.
- Environment: deployed development app on14October2026; separate current-source React/Uppy reproduction. Deployed revision unknown.
- Fixture: Draft Membership b4b69b77-a143-486b-aca0-9c3a053fd440, owned by the authorized Creator account.

## Reproduction

1. Create a Draft Membership; open Content, Add content, Video or Resource.
2. Fill Title and Description. Select a supported synthetic file using browse files.
3. The selected filename disappears. Press Save.
4. Video shows “Select a video file.”; Resource shows “Select a resource file.”

Observed for a valid2269-byte MP4 and Resource TXT/PDF/ZIP/DOCX/PNG/WAV fixtures under9KiB. No Video/Resource metadata or feed row is persisted. The Draft stays private; orders and entitlements are unchanged.

## Current-source reproduction and cause

A focused temporary React test imports the unchanged shared UppyFileUploader and actual Uppy core; only the Dashboard presentation and unused transfer plugins are mocked. With the same inline callback pattern used by both Membership editors, one real file-added event causes one file-removed event, three uploader instances and zero selected files. The expected retained-selection assertion fails. A stable callback control creates one instance, emits no removal and retains the selection.

Both Membership editors create handleFilesChange on each render. UppyFileUploader depends on that callback in its initialization effect. A parent update recreates the uploader; cleanup calls destroy(), which calls cancelAll()/removeFiles() and emits file-removed. Its still-attached change listener then clears the parent selection. The local cause is confirmed independently of the browser picker; deployed behavior is consistent with it, without claiming a verified deployed source revision.
