# BUG-084 — Social editor ignores restoring an initial link value

- Severity: Medium.
- Status: Confirmed in current-source isolated browser component; not fixed.
- Related case: PROF-018.
- Environment: unmodified SocialMediaInput, actual React/Framer Motion dependencies, isolated browser fixture, 29 October 2026.

## Reproduction

1. Mount with one existing Facebook link, `https://example.invalid/original`.
2. Open Facebook, change it to `https://example.invalid/changed-for-revert`, and confirm with Enter.
3. Reopen Facebook, enter the original value, and confirm with Enter.

The popup closes, but the callback still contains the changed URL. The original value is not restored. A second sequence that first clears the link reproduces the ignored restoration and leaves its URL empty.

`handleAdd` compares the entered value against `initialValuesById`, rather than the current link value. When the user enters the original value, the update block is skipped even though the current value differs.

Button and Enter confirmation for other changed values pass. Platform entries remain unique. This is a local editor defect; no deployed profile PUT or persisted-data loss is claimed. Normal deployed Additional-step access remains independently blocked by BUG-064.

## Evidence

Consolidated packet `isolated-actual-profile-social-and-location-controls-2026-10-29` contains before/after callback values, actual browser observations, source snapshots and an unmodified fixture screenshot. Synthetic controls reset; temporary tab and server closed. No cloud changes.
