# BUG-050 — Wrong-shaped saved collection data causes unhandled app errors

- Severity: Medium — persistent local collection corruption prevents normal app recovery.
- Case: CART-005, cart and wishlist wrong-shape investigation.
- Status: Confirmed for User, Creator, Admin and Guest in unchanged full current frontend. No fix.
- Environment: local current revision `12765d4568796f8472124383a221b74d82850c5b`, actual backend and private migrated PostgreSQL. Development error overlay is local; deployed presentation is unverified.

## Reproduction

Initialize one controlled local collection entry, then load or reload the application:

- `cart:v1`: `{"products":{},"loading":false,"total":0}`, with a valid empty wishlist; open Cart.
- `wishlist:v1`: `{}`, with a valid empty cart; open Explore.

Expected: invalid persisted collection shape is rejected or safely reset so normal collection controls remain usable. The catalog calls for investigation of this shape; no particular recovery interface is prescribed.

Actual: JSON parsing succeeds, but no collection schema check follows. Cart throws `products.filter is not a function`; Wishlist throws `products.map is not a function`. Normal app controls disappear and reload repeats the exception. A visible test-only collection reset restores the app; that is external fixture recovery, not a supported user recovery action.

Cart reproduces for User, Creator and Admin. Guest Cart crashes during the initial render before authentication denial can settle; this does not establish Guest authorization or protected-data exposure. Wishlist reproduces on public Explore for all four roles.

Malformed JSON is a passing control: both collections catch parsing failures. Cart add/remove and Wishlist toggle/reload recover normally. Guest cart data persists into a subsequent synthetic User session, where it can be inspected and removed; ordinary Guest Cart still requires login.

## Cause and evidence

`loadCartFromStorage` accepts parsed data as ShopCartState. Wishlist loading similarly casts parsed data to a Product array. Store preloading and selectors/checkout code use array methods on those unchecked values. Parse exception handling does not catch later shape errors.

[Existing browser batch](../evidence/browser-populated-reporting-batch-2026-10-03.json), key `local-current-app-real-backend-collection-storage-2026-10-09`, records visible first-party storage initialization, exact browser error snapshots/reloads, passing malformed-JSON controls, source hashes and unchanged database state. ## Scope and cleanup

Actual localStorage entries were initialized by the disposable site's visible fixture controls, without changing app sources. Browser permission denial for storage reads/writes was not tested. No paid or enrollment API request occurred; eleven grants and four existing fake orders remain unchanged. Local cart and wishlist were restored empty and normal User Cart verified. Cloud data/account unchanged; local fixtures retained for continued testing.
