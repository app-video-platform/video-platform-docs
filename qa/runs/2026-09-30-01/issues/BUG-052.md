# BUG-052 — Rejected landing Save escapes the click handler

- Severity: Medium — failed Save produces an unhandled rejection in addition to its inline error.
- Case: LAND-009; supporting ownership security evidence in JOURNEY-008.
- Environment: unchanged current local App and actual backend with migrated PostgreSQL. No deployed-overlay parity claim.

## Reproduction

1. As synthetic Creator B, open Creator A's Published Course landing builder URL.
2. The config GET returns403; generic controls remain visible with Access Denied.
3. Edit Marketing description and click Save.

Expected: contain the rejected Save, preserve draft/error feedback and avoid saved-success or unhandled runtime errors.

Actual: PATCH403 correctly prevents the foreign mutation and inline Access Denied remains, but an uncaught runtime-error overlay also appears. The async `save` function awaits `dispatch(...).unwrap()` without handling its rejection and is passed directly to the click handler. No saved-success claim is emitted; owner config remains unchanged.

The development overlay is the observed symptom; an equivalent deployed overlay is not claimed. The rejected promise is the underlying handling defect. Successful owned configuration was not altered. API ownership protection passes independently.

Existing browser batch key `local-current-app-actual-ownership-substitution-and-error-handling-2026-10-12` contains before/after DOM, actual rejected proxy response, source hash and persisted readback. No new evidence file.
