# BUG-011 — Authentication forms overflow narrow viewports

- Severity: Medium
- Status: Confirmed; not fixed in this test execution pass
- Related case: UX-015
- Role: Guest
- Environment: deployed frontend; independent browser session

## Reproduction

1. Open `/auth/login` as Guest.
2. Set the viewport to 320, 375, or 768px wide.
3. Inspect form fields and actions without horizontal scrolling.

## Expected

The sign-in form and its actions fit the viewport, with input contents and controls readable and reachable.

## Actual

Document width remains800px at each of these widths. Email and Password fields extend beyond the screen. At320px, the password visibility and Forgot Password controls are outside the initial viewport. The page fits1440px.

## Scope and limits

The local recovery password step also retains a500px document at320/375px, clipping fields/actions. It fits768/1440px. See `recovery-responsive-320.json`, `recovery-responsive-375.json` and [recovery screenshot](../evidence/recovery-375px.jpg). No password was entered.

The observed issue concerns layout and control reachability. It does not establish a password or Google sign-in failure. Signup also retains800px at320/375/768px and fits1440px; see `signup-responsive-320.json`, `signup-responsive-375.json`, `signup-responsive-768.json`, and [375px signup](../evidence/signup-375px.jpg). Other authentication screens and zoom remain separate variations.
