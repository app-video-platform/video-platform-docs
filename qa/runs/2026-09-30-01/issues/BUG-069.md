# BUG-069 — Uploaded Product presentation media returns AccessDenied

- Severity: High
- Status: Confirmed; not fixed in this test execution pass
- Related cases: ENV-006, MEDIA-003
- Environment: development backend, Spaces origin/CDN and deployed public Product page
- Fixture: synthetic Download `1a79acf6-71ad-4a36-85b9-33e63136bf84`

## Reproduction

1. As the synthetic Creator, create a disposable Download with one harmless stored text file.
2. Upload a valid 32×32 PNG as thumbnail and gallery image with `Content-Type: image/png`, and a valid one-second silent H.264 MP4 with `Content-Type: video/mp4`, through the normal media APIs.
3. Publish the synthetic Download through the normal API.
4. Read each returned presentation URL through the configured CDN and corresponding origin; open the public Product page.

## Expected

The Published Product's thumbnail, gallery image and promo video can be retrieved and displayed. Protected Download files remain accessible only through authorized signed URLs.

## Actual

All three media uploads return HTTP 200. The database retains three READY rows with the correct MIME types and sizes: two 99-byte PNGs and one 1,837-byte MP4.

All three presentation URLs return HTTP 403 / `AccessDenied` from both CDN and origin. The public page's two image elements complete with natural width/height zero. Its promo video remains unloaded with ready state zero; a keyboard playback attempt does not establish playback or a native video error.

The same fixture's private text file returns HTTP 403 unsigned, but authorized signed retrieval returns HTTP 200 with the exact expected bytes. This is not evidence of a general object-store outage.

## Evidence and limits

The consolidated browser evidence packet `deployed-public-media-cdn-denial-and-natural-cookie-expiry-2026-10-23` contains API responses projected without URLs, origin/CDN statuses, browser measurements, fixture validation and read-only database results.

The exact storage permission or URL configuration cause is not established. No bucket policy, ACL, CDN configuration or application implementation was changed. Correct-MIME API uploads are setup for this delivery test; the separate browser upload Content-Type issue remains BUG-042.

## Cleanup

The new Product was changed from Published to Hidden through the normal API. The database confirms Hidden and all three READY media rows. The harmless fixture is retained for diagnosis. The original three Published synthetic Downloads remain Published. No existing customer content or grant was changed.
