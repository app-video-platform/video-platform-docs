# BUG-033 — Storefront retains a failed profile-save alert after a successful retry

- Severity: Medium — successful recovery continues to look unsuccessful.
- Status: Confirmed in the deployed development browser.
- Cases: STORE-011, STORE-012; these original cases remain partially assessed.
- Fixture: OWNER-A, Creator. Only the Title field was saved; its original value was restored.

## Reproduction

1. Open the Storefront builder and edit Title.
2. Save 101 characters. The title remains unchanged and the page shows `Unable to load or save Storefront data` / `Update user details failed`.
3. Reopen Title and save a valid 100-character synthetic title.
4. Observe the new title in the builder while the previous failure alert remains.
5. Reload: the new title persists and the alert disappears. The owner and a separate Guest public Storefront both show the saved title.

A fresh repetition with another overlong rejection followed by saving the original valid title also retains the old alert. The original title was restored and checked after reload on all three views before that repetition.

## Expected and actual

After a successful retry, the previous failure alert clears. Instead, the saved value is correct but the page continues reporting failure until reload. The rejected attempt also closes the inline editor; no field-specific error remains visible there.

## Implementation evidence

The profile update reducer sets `error` on rejection. Its pending and fulfilled handlers do not clear that error. The Storefront page renders the authentication error in its page-level alert. This matches the deployed retry observation; no fix was made.

## Scope and cleanup

The invalid request's HTTP status/body was not inspected. This finding concerns browser feedback, not a failure to persist the valid title. Other profile fields, role changes, config mutations and provider operations were not performed. Original title restoration was verified in browser; a later read-only database tunnel timed out, so no new database fingerprint check is claimed. A final clean-page reload became blank.
