# BUG-039 — Previous Product response replaces the current Overview

- Severity: Medium — valid Product inspection can show a false missing-product state.
- Status: Confirmed in the actual current frontend with controlled responses; deployed response-order reproduction remains unverified.
- Case: PROD-007.
- Observed: 7 October 2026.

## Expected

After navigating from Product A to B, A's outstanding request cannot replace B's data or end B's loading state. A successful B response keeps B's Overview visible.

## Actual and reproduction

1. Run the current application router, providers, Redux store and Axios client with the retained synthetic response fixture. Let initial authentication/profile and Product requests settle.
2. Delay future catalog responses. Navigate within the same router to Course A, then Download B. Exactly one request for each Product remains pending.
3. Resolve B with HTTP200. Its correct title and empty Download outline appear at B's URL.
4. Resolve the earlier A request with HTTP200. B's URL stays selected, but the page changes to **Product not found / This product is not available.** All requests have completed successfully.

The same failure occurs after a fresh StrictMode bootstrap with several outstanding A requests. A separate ordered control resolves A while B is still pending: the page prematurely leaves loading and shows Product not found. When B eventually resolves, its correct Overview returns. Reload with restored responses also recovers.

## Implementation and limits

`getProductById.fulfilled` unconditionally sets `currentProduct` and clears loading in `product.slice.ts`. It does not reject an older request's completion. Product Overview correctly checks the stored Product ID against the route, so it rejects A at B's URL and renders the missing-product state. The observed failure is a false unavailable page, not presentation of A's content as B.

The fixture controls only response completion through visible buttons and navigates using links inside the actual application's BrowserRouter. No application source, store reducer or component behavior is modified. The one-request-per-Product reproduction establishes that duplicate development effects are not required.

This is local browser evidence with synthetic profiles and API responses. No deployed version equivalence, cloud response ordering, data mutation, permission change or backend fault is claimed.
