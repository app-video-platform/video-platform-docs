# BUG-037 — Failed profile saves do not stop onboarding advancement

- Severity: Medium — the wizard progresses after a rejected save.
- Status: Confirmed in the isolated current Onboarding component; deployed save failure not injected.
- Case: PROF-001.
- Roles: Synthetic USER, CREATOR and ADMIN.
- Observed: 4 October 2026. Report finalized from retained evidence on 7 October.

## Expected

A rejected profile update must not imply that a step was saved. The user needs a failure/retry state before relying on progression as successful persistence.

## Actual and reproduction

1. Mount the actual unmodified wizard in the diagnostic route with an incomplete synthetic profile and controlled profile PUT failures.
2. Submit valid Title, then valid Bio/Tagline, then a valid Website.
3. Each update receives the controlled 503 response, but the wizard advances Basic → About → Additional → summary.
4. The synthetic stored profile remains empty and incomplete. No validation error is present on the destination step.

The 69 boundary trials separately prove that invalid inputs send zero new updates while valid inputs dispatch one failed update and advance. Successful-response controls traverse the same steps and preserve the supplied fields in fixture state.

## Implementation and limits

`MultiStepForm.onStepValid` dispatches `updateUserDetails` and immediately calls `nextStep`; it does not await or unwrap the save. The component does not render the authentication store's rejected-update error.

This is an actual frontend failure-response test with synthetic transport, not evidence of a specific deployed HTTP failure or lost cloud record. BUG-035 prevents the normal route from reaching the wizard. Real persistence and reload remain unverified; no real profile mutation occurred.
