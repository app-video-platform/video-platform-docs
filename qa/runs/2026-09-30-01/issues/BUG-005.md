# BUG-005 — Library announces the wrong selected tab

- Severity: Low — accessibility state disagrees with the current section.
- Case: ACCESS-007 / admin-library-courses-selected-state
- Deployment versions: unknown
- Roles: ADMIN and USER reproduced

## Reproduction

1. Open `/app/library/all-products`.
2. Click Courses and wait for `/app/library/my-courses` to settle.
3. Inspect the tab accessibility state.

Expected: Courses has `aria-selected=true`; All products is false.

Actual: All products remains selected and Courses is false. Navigation and route-based visual styling work. The same false selection was sampled for Download Packages, Consultation sessions and Wishlist.

Evidence: [stable DOM observations](../evidence/library-tab-selection.md), [Courses screenshot](../evidence/library-courses-tab.jpg).

Suspected cause: local LibraryPage uses pathname segment 2, which is `library` rather than the child section at segment 3. This is not proof of the deployed revision. No implementation change made.

No cleanup required.

User reproduction: `/app/library/my-wishlist` contains the synthetic Consultation while All products is still selected and Wishlist false. See [User Wishlist](../evidence/user-wishlist.jpg).
