# BUG-091 — Enter can submit a stale autocomplete suggestion after replacing the query

- Severity: P2 — search usability.
- Status: Open; reproduced in deployed browser on 1 November 2026.
- Related case: UX-015; also relevant to UX-008 search interactions.
- Environment: synthetic Creator;375px viewport. Source timing condition is not known to be width-specific.

1. Open Product search and enter `QA-2026-09-30-01`. Wait for suggestions; Decimal Pricing is highlighted first.
2. Replace the field with `QA-2026-09-30-01 Curriculum` and immediately press Enter.
3. The input retains Curriculum but the URL/results heading search for Decimal Pricing from the previous query.

Expected: replacing the query must not silently submit a suggestion from the previous query.
Actual: a prior highlighted title is selected before suggestions update. Normal Submit search uses the current input and correctly recovers the Curriculum result.

Current SmartSearch source debounces its query by250ms, retains existing suggestions/open state during that interval, and handles Enter using `suggestions[highlight]?.title ?? rawQuery`. This supports a stale-selection timing cause; exact deployed revision was not established.

Evidence: consolidated packet `deployed-remaining-responsive-primary-and-authoring-actions-2026-11-01`. Both initial incidental mismatch and deliberate reproduction are retained; transient heading snapshots are not counted as successful searches. No mutation or network interception was used. No fix applied.

Query-keyed suggestions isolate late prior responses. Search supplies the combobox/listbox/option relationships and selected-current active descendant.
