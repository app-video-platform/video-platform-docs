# BUG-036 — Onboarding validation errors are not linked to their fields

- Severity: Medium — visible validation is missing programmatic field/error associations.
- Status: Confirmed in the isolated current Onboarding component; deployed wizard behavior unverified because of BUG-035.
- Case: UX-016.
- Roles: Synthetic USER, CREATOR and ADMIN.
- Observed: 4 October 2026. Report finalized from retained evidence on 7 October.

## Expected

Visible field labels associate with their inputs. An invalid field exposes its error text through a valid description reference and communicates its invalid state.

## Actual and reproduction

1. Mount the actual unmodified wizard in the diagnostic frontend fixture; advance to Basic Profile.
2. Enter one character in Title, blur and activate Next.
3. The visible minimum-length message appears and submission is blocked.
4. The input has `aria-describedby="title-error"`, but no element has that ID. Its `aria-invalid` attribute is absent and its associated label collection is empty.

Bio and Tagline controls likewise have unassociated visible labels and no programmatic linkage to the visible validation errors. The three-role boundary matrix records these DOM properties. A separate keyboard Enter reproduction stays on Basic Profile, shows the error and sends no profile PUT; keyboard submission itself is functional.

## Implementation and limits

The step components render standalone labels without `htmlFor`. Title passes a description ID but renders the error paragraph without that ID. They do not supply the shared Input/Textarea `error` prop that creates the corresponding error element and invalid attribute.

Actual component DOM was inspected; a screen reader was not used and no announcement behavior is claimed. Other form families remain part of the broader unfinished case. Synthetic profile responses only; no real account change.
