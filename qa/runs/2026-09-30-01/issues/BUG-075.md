# BUG-075 — Public Storefront replaces saved biography and title with placeholders

- Severity: Medium — saved public profile copy is not presented to visitors.
- Status: Confirmed in the deployed app; not fixed.
- Cases: STORE-011, UX-013.
- Account: synthetic Creator only. No personal profile changed.

## Reproduction

1. In Storefront Builder, edit Bio and save a synthetic239-character biography through the normal inline Save control.
2. Confirm that the builder displays the new copy. Profile GET and public Storefront GET return that same biography; their SHA256 values match the submitted text.
3. Open the public Storefront and reload it.
4. Observe the public biography and title.

## Expected

Public Storefront displays the saved nonempty biography and title. Empty-field placeholders are used only when appropriate.

## Actual

The public biography says `Add a public bio.` and the title says `Creator`. The real nonempty title is present in the public API, and the saved biography is present in both profile and public APIs. The problem reproduces at375px and1440px, after public-page reload, and across the additional responsive preview reads. The authenticated builder displays the actual biography correctly. Theme changes save and appear publicly, so this is not a blanket profile-save or Storefront-save failure.

## Implementation and evidence

In `storefront-public-page.component.tsx`, `renderEditable` returns the editable renderer, then the supplied fallback, then the value. The public page has no editable renderer. The Bio and Title calls supply nonempty fallbacks, which therefore replace nonempty saved values. This is consistent with the deployed API/browser observations.

Consolidated packet `deployed-responsive-builder-boundaries-and-public-profile-fallback-2026-10-26` contains real Save/Reset/public-preview/reload observations, matching biography hashes, source snapshots and cleanup proof. No application source was changed.

## Cleanup

The temporary biography was cleared through the supported profile API. Original Storefront and landing-page business configuration values were restored. The synthetic profile's original SQL NULL biography is now an empty string because null updates are ignored; all other full-profile fields match. Both values produce an empty public biography. A newly created landing-config row remains at the original default values on an already Hidden synthetic Product. No role, publication, payment, booking or new binary upload occurred.
