# BUG-023 — Deployed Consultation authoring has no weekly availability persistence

- Severity: Medium — schedule edits appear saved but the deployed database/API lack the expected weekly metadata.
- Status: Confirmed deployment mismatch; no implementation or deployment changes in this pass.
- Case: CONS-002. Related: CONS-003/004 and CONS-001 reload obstruction.
- Role: OWNER-A, CREATOR; supplementary anonymous read of a Published synthetic Consultation.
- Observed: 2 October 2026. Deployed revisions remain unknown.
- Draft fixture: `f23aedae-ab06-4808-8623-1c69e799ffa6`.

## Reproduction

1. Create a disposable Draft Consultation and stay in the initial workspace.
2. Open Availability, enable Saturday and disable Tuesday.
3. Change Monday from09:00–17:00 to09:00–12:00 and add a second12:00–17:00 range.
4. Wait for the Unsaved changes indicator to clear. Observe no save failure.
5. Compare with read-only database schema and migration history.

## Expected

The schedule edits persist as weekly day/window metadata. The current test catalog and backend checkout define `consultation_availability_days`, `consultation_availability_windows` and migration39 for that persistence.

## Actual

The deployed database has neither availability table and no matching migration39 record. Its Consultation table has no alternative weekly JSON column. A public read of the other Published synthetic Consultation also has no `weeklyAvailability` field in its details response.

Duration, meeting method, instructions, buffers, daily capacity, confirmation message and cancellation policy do persist in this same database. This distinguishes the missing schedule capability from a total save or connectivity failure.

The editor keeps the modified days/ranges in the current session and clears its unsaved indicator. Browser Back from private preview then hits the separately confirmed BUG-001, so browser rehydration cannot be evaluated here. The schema/API mismatch is confirmed; its precise deployed revision and release cause are not established. No booking inventory, event or timezone calculation was inferred or tested.
