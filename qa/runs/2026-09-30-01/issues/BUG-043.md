# BUG-043 — Removed gallery file is silently ignored when selected again

- Severity: Medium — restoring a removed image requires remounting the component or choosing a different file.
- Status: Confirmed in the current Media component with real Uppy/file selection and controlled successful local callbacks. Deployed reproduction remains unverified.
- Cases: MEDIA-005, related MEDIA-007.
- Observed: 8 October 2026.

## Expected

After deleting a saved gallery image, the freed slot accepts the same valid file again.

## Actual and reproduction

1. Render the current `ProductMediaSection` and Uppy uploader with synthetic Product metadata. Use an explicit MIME diagnostic callback so the separate upload-header defect BUG-042 does not prevent the successful-upload prerequisite.
2. Select the valid `image.png` fixture. One POST returns200; the saved gallery article shows the filename and Position1.
3. Remove that image. DELETE returns204 and the component displays `No gallery images yet`.
4. Select the exact same file again, keeping its name, size and modification time. The gallery remains empty, no new POST is sent and no actionable error appears.
5. Reload the temporary page, enable the same MIME control and select the unchanged file. A new POST returns200 and the gallery article appears, confirming the file itself is acceptable.

`uploadedGallerySignaturesRef` retains successful `name:size:lastModified` signatures for the component lifetime. Removal does not clear the corresponding signature; `handleGalleryFiles` filters the selection to an empty list and reports a successful state without uploading it.

## Scope and evidence

This is an isolated current-component lifecycle defect, not proof of a completed deployed upload/delete journey. The local callback changes MIME only as a diagnostic control and uses synthetic metadata; no application source, cloud object or live account was changed. Ordinary fresh-file capacity checks pass in the actual backend, so the observed suppression is in the browser component.

- [Browser batch](../evidence/browser-populated-reporting-batch-2026-10-03.json): `isolated-media-request-mime-and-selection-recovery`.
- [Backend capacity batch](../evidence/backend-content-session-batch-2026-10-03.json): `migrated-postgresql-media-ownership-and-capacity`.

The browser entry retains the upload/delete/reselection/reload observations and actual request list. No application fix is included.
