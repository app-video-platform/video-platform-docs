# BUG-085 — Reverse-geocoding failure throws without visible feedback

- Severity: Medium.
- Status: Confirmed in current-source isolated browser component; not fixed.
- Related case: PROF-017.
- Environment: unmodified OSMLocationSearch and installed autocomplete dependency; declared synthetic fetch responses, 29 October 2026.

## Reproduction

1. Type a synthetic location query and return a successful autocomplete result.
2. Select the result.
3. Return HTTP503 with an error object from the reverse-geocoding dependency.

The input displays the selected location, but the callback remains null. The browser records `TypeError: Cannot read properties of undefined (reading 'city')` in `fetchStructuredAddress`. No visible error explains the failed selection.

The wrapper reads JSON without checking `res.ok`, then dereferences `data.address.city` without an error handler. The error object has no address. Successful synthetic search/reverse responses map city, country, latitude and longitude correctly. A rejected search request instead displays `No locations`, which does not distinguish an outage from no matches.

This proves component error handling for the controlled503 response. It does not prove live Nominatim availability, deployed onboarding persistence or real geolocation permission behavior. No real coordinates or external request were used. The wrapper and dependency expose no observed current-location control; the catalog permission branch remains a separate clarification.

## Evidence

Consolidated packet `isolated-actual-profile-social-and-location-controls-2026-10-29` contains component browser observations, bounded exception details, declared transport fixture and source snapshots. Synthetic controls reset; temporary tab and server closed. No cloud changes.
