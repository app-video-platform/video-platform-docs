# BUG-060 — Changing workspace tabs or leaving cancels pending nested edits

- Severity: High — normal navigation silently loses authored content.
- Case: CONTENT-014, nested autosave navigation race.
- Environment: current frontend `12765d4568796f8472124383a221b74d82850c5b`, actual isolated backend `1b860413436d5f850af0ecc228c5b613ebae4836`, migrated PostgreSQL. No deployed reproduction claimed.

## Reproduction

1. Open a functioning newly created Course workspace with a section and lesson, or a Download workspace with a file group.
2. Change the section, lesson, or file group description.
3. Before the two-second autosave runs, select Basics. For a lesson, close its drawer and immediately select Basics.
4. Return to Curriculum or Files and wait longer than two seconds.
5. Compare the visible description with a fresh authorized Product read.

Expected: navigation preserves the pending save, or clearly warns that unsaved changes remain. Returning to the editor should not silently treat unsaved text as its saved baseline.

Actual: the edited description remains visible, but no PATCH reaches the backend and the persisted description remains unchanged. Waiting after returning does not retry the save. All three nested entity types reproduce this behavior.

A separate departure check changes a section and lesson in a disposable Course, or a file group in a disposable Download, then immediately clicks the header Products button. Navigation succeeds without a warning. Neither nested edit persists. The measured edit-to-departure action sequences finish within two seconds. The shared Product flush does not flush these nested editors.

## Cause and evidence

`useSectionAutosave` and `useLessonAutosave` cancel their pending timeout on cleanup. Switching workspace tabs unmounts the nested editors. On remount, each hook initializes its saved snapshot from the still-dirty local value and schedules no save. The header Back handler flushes shared Product details only.

[Existing browser batch](https://github.com/app-video-platform/video-platform-docs/blob/main/qa/runs/2026-09-30-01/evidence/browser-populated-reporting-batch-2026-10-03.json), key `nested-autosave-navigation-rejection-and-recovery-2026-10-18`, retains actual browser states, timestamped request traces, authorized API readbacks, Admin controls, final SQL verification and source snapshots.

## Boundaries and recovery

Jumping within Curriculum does preserve a pending section save. Closing a lesson drawer alone also preserves its save, as established in CONTENT-009. The failure requires leaving the nested workspace content before the timer fires.

Controlled 503 saves show a global Error indicator and console diagnostics. Once the fault is removed, a subsequent normal edit saves successfully. These transport checks are distinct from the silent navigation loss.

The original retained Course and Download descriptions are restored and verified. The two new synthetic departure Products remain private Drafts. No cloud mutation, upload, payment, implementation fix or deployment occurred. Saved editor reopening still fails with existing BUG-001, independently of this issue.

### Publication correction confirmation — 31 October 2026

The unchanged full app with the actual local backend and PostgreSQL (40 migrations)
reproduces the pending-section loss during a publication recovery flow. After a
declared `details.sections` publication rejection, editing the section description
and immediately switching to Readiness leaves the canonical description empty;
no section PATCH is recorded for that first edit. Keeping Curriculum open for the
normal autosave produces PATCH 200 and the exact corrected description persists.
The subsequent real backend publication returns 200 and the public page retains
that description after reload. The injected rejection only controls the initial
validation response; nested saves and the successful retry use the real backend.
No deployed data or implementation was changed. Consolidated evidence key:

## Resolution and verification — 3 November 2026

Failures retain dirty editors and expose retry; retry saves in place before another navigation choice. Ordering shares the queue; deletion waits for relevant writes.
