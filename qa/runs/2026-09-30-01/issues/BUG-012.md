# BUG-012 — Public Explore navigation overflows phone and tablet screens

- Severity: Medium
- Status: Confirmed; not fixed in this test execution pass
- Related case: UX-015
- Role: Guest
- Environment: deployed frontend; independent browser session

## Reproduction

1. Open `/app/explore` as Guest.
2. Use a320,375, or768px viewport.
3. Inspect search and authentication controls without horizontal scrolling.

## Expected

Public navigation, search and authentication actions fit the narrow layout or use a suitable collapsed navigation control.

## Actual

The navbar requires approximately861px. At320/375px, the search input is partly clipped and Explore, Log In and Register are outside the initial viewport. At768px, Register is still outside the viewport. The observed1440px layout fits.

- [375px screenshot](../evidence/explore-375px.jpg)
- Geometry: `explore-responsive-320.json`, `explore-responsive-375.json`, `explore-responsive-768.json`, `explore-responsive-1440.json`

## Scope and limits

Guest synthetic Published Consultation detail also reproduces861px document width at375/768px and fits1440px. See `public-consultation-responsive-375.json`, `public-consultation-responsive-768.json`, and [375px detail](../evidence/public-consultation-375px.jpg). Search, Cart, other signed-in headers, and zoom need their own observations. It does not assert an authentication or search API failure.
