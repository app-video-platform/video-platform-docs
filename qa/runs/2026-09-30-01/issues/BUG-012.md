# BUG-012 — Marketplace navbar overflows narrow screens and search overlaps Explore

- Severity: Medium
- Status: Confirmed; not fixed in this test execution pass
- Related case: UX-015
- Roles: Guest, User, Creator and Admin; scoped observations below
- Environment: deployed frontend; independent browser session

## Reproduction

1. Open `/app/explore` as Guest.
2. Use a320,375, or768px viewport.
3. Inspect search and authentication controls without horizontal scrolling.

## Expected

Public navigation, search and authentication actions fit the narrow layout or use a suitable collapsed navigation control.

## Actual

The navbar requires approximately861px. At320/375px, the search input is partly clipped and Explore, Log In and Register are outside the initial viewport. At768px, Register is still outside the viewport. The observed1440px layout fits.

Keyboard recovery works: from search, Tab reaches Submit search then Explore; Enter navigates to `/app/explore`. This is a pointer overlap, not a permanent keyboard trap. Earlier wide-screen geometry fit checks did not test hit targets.

This is consistent with the30px overlap; deployed source revision is unknown, so the diagnosis remains a source-backed hypothesis. No fix applied.
