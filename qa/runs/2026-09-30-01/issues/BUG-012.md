# BUG-012 — Marketplace navbar overflows narrow screens and search overlaps Explore

- Severity: Medium
- Status: Confirmed; not fixed in this test execution pass
- Related case: UX-015
- Role: Guest
- Environment: deployed frontend; independent browser session

## Reproduction

1. Open `/app/explore` as Guest.
2. Use a320,375, or768px viewport.
3. Inspect search and authentication controls without horizontal scrolling.

## Expected

Public navigation, search and authentication actions fit the narrow layout or use a suitable collapsed navigation control.

## Actual

The navbar requires approximately861px. At320/375px, the search input is partly clipped and Explore, Log In and Register are outside the initial viewport. At768px, Register is still outside the viewport. The observed1440px layout fits.

## Desktop pointer overlap — 8 October 2026

Actual deployed Guest testing also finds a pointer reachability failure at1280×720 and1440×900. Open the Published synthetic Course `/app/product/cb045295-cf70-445c-99a7-46fc0618e58e` and click the center of the navbar Explore link. Focus lands in Product search and the route stays on the Course.

At1280px, the450px search input spansx401.05–851.05 while Explore spansx821.05–878.20; its center is covered by the input. At1440px, both shift80px and the overlap persists. Read-only `elementsFromPoint` confirms INPUT above the link. No toast is present in these deployed reproductions. The same behavior occurs in the current full frontend with a controlled local User profile.

Keyboard recovery works: from search, Tab reaches Submit search then Explore; Enter navigates to `/app/explore`. This is a pointer overlap, not a permanent keyboard trap. Earlier wide-screen geometry fit checks did not test hit targets.

Current source has `.smart-search-container` max-width400px inside a flex container, while `.search-form` has min-width450px and the following link gap is20px. This is consistent with the30px overlap; deployed source revision is unknown, so the diagnosis remains a source-backed hypothesis. No fix applied.
