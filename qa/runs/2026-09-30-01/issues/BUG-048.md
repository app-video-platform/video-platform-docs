# BUG-048 — A cart item without an ID cannot be removed or moved to Wishlist

- Severity: Medium — a malformed entry prevents checkout and normal cart recovery.
- Case: CART-001 supplemental removal recovery; fixture from CART-021.
- Status: Confirmed in the current frontend; no application change.
- Environment: isolated complete frontend, synthetic User and controlled HTTP summaries. Local revision `12765d4568796f8472124383a221b74d82850c5b`; deployment parity unverified.

## Reproduction

1. Supply a positive-price Product summary without an `id` in the isolated catalog fixture.
2. Add it through the normal Explore Add to cart button and open Cart.
3. Click Proceed: the missing-identity validation correctly blocks checkout.
4. Click the enabled Remove button, then Move to wishlist.
5. Reload Cart.

Expected: malformed data is rejected before insertion, or the user can remove the offending entry through normal controls.

Actual: both actions leave the one-item €10 cart unchanged. Reload retains it. Checkout continues to reject the cart, and there is no normal clear-cart control.

The current Cart handlers require `prod.id` before dispatching removal or movement. Explore and the cart reducer accept the summary without an ID; local persistence retains it. This explains the observed behavior. It does not establish that the deployed backend emits malformed summaries.
