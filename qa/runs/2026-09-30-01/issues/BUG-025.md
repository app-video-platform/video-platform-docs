# BUG-025 — Admin landing builder omits another Creator's profile

- Severity: Medium — the live landing preview differs from the authorized private preview.
- Case: LAND-008, cross-owner Draft Course.
- Account: OWNER-A, ADMIN. Deployed revisions remain unknown.
- Product: existing Draft Course `b48d11d4-a0ec-4126-a416-d536e887dfd9`, owned by a different Creator. Read-only checks; no edits or Save.

## Reproduction

1. As Admin, search Admin Products for the existing `test RTE` Course.
2. Open its Product Overview, then Edit landing page.
3. Observe that the Creator section checkbox is checked, but the live landing preview has no Creator identity or section.
4. Open the same Product's authorized private preview at `/app/products/{id}/preview`.

Expected: both previews include the Product owner's available public profile when the Creator section is enabled. Actual: private preview renders the owner's name, title and bio; the builder omits that region. The Product outline renders in both. Public Draft view separately returns Product unavailable as expected.

One cross-owner Course comparison was observed. A repeat navigation was interrupted by `ERR_CONNECTION_CLOSED`; that interruption is not used as additional reproduction evidence. Other Product types and saved-config behavior remain untested. No authenticated HTTP status is inferred from browser logs.

Local implementation supports the observed difference: ProductLandingPageBuilder passes the current user and Creator Storefront theme to the shared view model, and unconditionally requests Creator Storefront config. ProductPreview instead loads the Product owner's public Storefront for Admin/non-owner sessions and passes it to the shared view model. This is supporting code evidence; the deployed revision and request-level cause are not verified.

Cleanup: no Product, landing config or Creator profile was changed.
