# BUG-008 — Profile Save ignores field validation

Severity: Medium. Case PROF-005. OWNER-A, CREATOR. Deployed revisions unknown.

## Reproduction

1. Open Settings → Profile.
2. Enter a 29-character Bio using native browser input, blur to Title, and click Save.
3. Repeat with a 9-character Tagline and malformed Website (`not a website`).
4. Enter a 121-character Tagline natively, blur, and Save.

Expected: minimum Bio/Tagline, maximum Tagline and URL validation display errors. Actual: no errors appear; Save shows `Product created successfully!`.

Native-input confirmation: [short Bio](../evidence/profile-native-short-bio.json), [Tagline and Website](../evidence/profile-native-invalid-fields.json), [upper boundaries](../evidence/profile-native-boundaries.json).

## Corrected Bio maximum observation

The Bio HTML maximum250 works with native input: attempting251 characters stops at250. An earlier automation fill produced251 and bypassed the native maxlength constraint. That observation is retained as historical tooling evidence, and is excluded from the confirmed defect. The latest results supersede its original interpretation. Tagline121 remains a real native-input failure.

Local source defines Bio30–250, Tagline10–120 and website validation, but Save directly displays a toast rather than submitting validation. This is a source hypothesis for deployed behavior; deployed revision is unknown.

Profile persistence is a separate cataloged limitation. Native-test edits cleared on reload and no profile mutation was observed in the database. These observations establish missing local validation, not a successful profile mutation.
