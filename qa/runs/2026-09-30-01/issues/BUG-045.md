# BUG-045 — Unread notifications have no visible state indicator

- Severity: Low — users cannot distinguish unread notification state in the menu.
- Status: Confirmed in the current frontend dropdown/store/listeners with controlled local HTTP responses. Deployed populated-state reproduction remains unverified.
- Case: LOCAL-002.
- Observed: 8 October 2026.

## Expected

An unread success notification has a visible unread indicator. Reducer actions do not imply that mark-read or remove controls exist in the normal UI.

## Actual and reproduction

1. Render the actual store, Product async thunks/listeners and notification dropdown with a synthetic Creator profile and initially empty notification list.
2. Resolve a real client Product request through the controlled loopback response. The actual fulfilled listener appends `Product Created` with `isRead: false`.
3. Open the current bell menu. The entry is present, but no unread marker is rendered. Seven successive fulfilled actions produce seven unread entries and still zero marker nodes; retry controls reach ten unread entries with the same behavior.
4. As a fixture-only diagnostic, dispatch the existing mark-as-read reducer for the first entry. One marker node then appears for `isRead: true`, but its height is0 and background transparent, so it remains visually absent. This diagnostic is not an available product menu action.

The component condition uses `notification.isRead` to render `notification-is-read-bubble`; unread entries do not render it. The current stylesheet contains no styling for that empty marker. No alternative unread badge or label is exposed in the inspected menu/trigger.
